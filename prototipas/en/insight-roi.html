ROI and measurement

How to judge real AI ROI — and why saved hours mean nothing

“We freed 200 hours a month” is not a result. The result is what happened to those hours: whether they became revenue, lower cost, or simply other work.

Most AI projects report activity: how many people started using a tool, how many prompts were written, how many hours were “saved”. That is convenient, because a number can always be found. That is also the problem — such a number does not answer whether the investment paid back.

An hour has value only when it is converted. If people fill saved time with other unpaid work, the economic effect is zero. If the same work is now faster but with more errors, the effect can be negative.

Realised AI effect = + additional gross profit
+ real cost reduction
+ losses avoided
− implementation cost
− operating cost
− error cost

The formula corrects three common mistakes. First — counting only the pluses. Operations and errors belong to the result. Second — changing the metric after the project so it looks better. You must measure the same thing, with the same method. Third — publishing an effect without a baseline. Without a starting state there is no result, only an opinion.

That is why every DIPA stage follows the same sequence: BASELINE → CHANGE → MEASURE → GATE. GATE can be Scale, Change or Stop. Stop is a normal result — it saves money that would have been spent on expansion without a case.
